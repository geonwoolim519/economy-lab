나는 "이코노미랩(Economy Lab)"이라는 인터랙티브 경제학 학습 웹사이트를 만들고 싶다.

## 1. 서비스 컨셉

이코노미랩은 경제학을 잘 모르는 한국어 사용자를 위한 인터랙티브 경제학 학습 사이트다.

기존 경제학 사이트들은 영어 용어와 복잡한 그래프, 많은 숫자를 중심으로 구성되어 있어 경제학 기초가 부족한 사람이 사용하기 어렵다.

이코노미랩은 경제학 개념을 단순히 설명하거나 암기시키는 것이 아니라,

"직접 조작 → 그래프 변화 → 결과 확인 → 왜 그런지 설명 → 경제 원리 이해"

의 과정을 통해 경제의 인과관계를 직관적으로 이해하도록 만드는 것이 핵심이다.

주요 타깃은:
- 경제학을 처음 배우는 사람
- 경제학원론을 공부하는 대학생
- 경제학 그래프가 익숙하지 않은 사람
- 경제 개념은 알고 있지만 원인과 결과의 연결이 헷갈리는 사람
- 경제 뉴스를 이해하고 싶은 일반 사용자

전체 UI와 설명은 한국어를 기본으로 한다.


## 2. 핵심 철학

이 사이트에서는 경제학 용어를 먼저 던지지 않는다.

예를 들어,

나쁜 방식:
"수요곡선의 우측 이동은 균형가격과 균형수량을 상승시킨다."

좋은 방식:
"소비자의 소득이 증가하면 시장에서는 어떤 일이 일어날까요?"

사용자가 슬라이더를 조작한다.

소득 증가
→ 소비자의 구매 능력 증가
→ 상품에 대한 수요 증가
→ 수요곡선 오른쪽 이동
→ 새로운 균형 형성
→ 균형가격 상승
→ 균형수량 증가

그리고 마지막에
"이 현상을 경제학에서는 '수요 증가'라고 합니다."
라고 용어를 연결한다.

즉, "용어 → 암기"가 아니라
"현상 → 조작 → 원인 → 결과 → 용어"
순서로 학습하도록 설계한다.

## 4. 디자인 방향

전체적으로 모바일 학습 앱처럼 디자인한다.

PC 대시보드처럼 많은 정보를 한 화면에 배치하지 않는다.

"모바일 우선(Mobile First)"으로 설계한다.

기준 화면:
375px ~ 430px 정도의 스마트폰 화면

PC에서도 사용할 수 있지만 모바일에서 가장 편하고 자연스럽게 보여야 한다.

디자인 키워드:
- 깔끔함
- 친근함
- 직관적
- 교육적
- 현대적
- 차분함
- 과도하게 금융 서비스처럼 보이지 않음
- 초보자가 부담 없이 접근할 수 있음

화면마다 정보량을 줄이고 충분한 여백을 사용한다.

한 화면에서는 하나의 질문 또는 하나의 경제 원리에 집중한다.

- 균형가격과 균형수량
- 가격 변화와 수요량
- 가격 변화와 공급량
- 초과수요
- 초과공급

LEVEL 02
시장과 정책

- 소득 변화
- 생산비용 변화
- 세금
- 보조금
- 가격상한제
- 가격하한제
- 탄력성

LEVEL 03
거시경제

- GDP
- 실업률
- 인플레이션

## 9. 핵심 실험 화면

첫 번째 실험은 "수요와 공급"으로 만든다.

실험 시작 전에 아주 쉬운 질문을 보여준다.

예:

"치킨 가격이 올라가면
사람들은 치킨을 얼마나 살까요?"

사용자가 직접 가격 슬라이더를 조작한다.

예:

치킨 가격
₩10,000 ─────●──── ₩20,000

슬라이더를 움직이면 그래프가 실시간으로 변화한다.

그래프에는:
- 가격
- 수량
- 수요곡선
- 공급곡선
- 균형점

등을 표시한다.

그래프는 모바일 화면에 맞게 단순하고 크게 표시한다.


## 10. 실험 결과

사용자가 값을 조작하면 바로 결과를 보여준다.

예:

"가격이 상승했습니다."

"수요량이 감소했습니다."

그리고 그래프에서 변화가 시각적으로 보이도록 한다.

결과 아래에는:

[🤔 왜 이렇게 됐나요?]

버튼을 배치한다.


## 11. "왜?" 기능

이코노미랩의 가장 중요한 기능이다.

사용자가 조작한 값에 따라 인과관계 설명이 달라져야 한다.

예:

생산비용 증가

↓

기업의 생산 부담 증가

↓

같은 가격에서 공급하려는 양 감소

↓

공급곡선 왼쪽 이동

↓

시장에 공급되는 상품 감소

↓

가격 상승

↓

높아진 가격으로 거래량 감소

마지막에는:

"핵심 원리"

공급 감소 → 가격 상승 → 거래량 감소

처럼 한 줄로 정리한다.

설명은 경제학 교과서처럼 어렵게 쓰지 말고 중학생도 이해할 수 있을 정도로 쉽게 작성한다.

필요한 경우 어려운 경제학 용어를 괄호 안에 함께 표시한다.

예:
"상품을 사려는 사람이 많아졌습니다. 이것을 경제학에서는 '수요 증가'라고 합니다."


## 12. 학습 방식

각 실험은 여러 STEP으로 나눈다.

예:

STEP 1
"가격이 올라가면 어떻게 될까요?"

→ 사용자가 가격 조절

STEP 2
"이번에는 소비자의 소득을 올려봅시다."

→ 사용자가 소득 조절

STEP 3
"이번에는 생산비용을 올려봅시다."

→ 사용자가 생산비용 조절

각 STEP에서는 하나의 인과관계만 집중적으로 보여준다.

실험이 끝나면:

"오늘 발견한 경제 원리"

라는 요약 카드를 보여준다.

예:

🧠 오늘 발견한 경제 원리

"생산비용이 증가하면 공급이 감소하고,
그 결과 균형가격은 상승하고 균형수량은 감소할 수 있습니다."

[이 원리 저장하기]


## 13. 탄력성 실험

두 번째 주요 실험으로 탄력성을 구현할 수 있도록 구조를 만든다.

사용자가 가격을 조절하면:

가격 +10%
→ 수요량 -3%

등의 변화가 표시된다.

그리고:
- 탄력적
- 비탄력적
- 단위탄력적

개념을 쉽게 설명한다.

가격 변화와 총수입의 관계도 시각적으로 보여준다.

중요한 것은 공식만 보여주는 것이 아니라:

가격 변화
→ 수요량 변화
→ 총수입 변화

의 인과관계를 보여주는 것이다.


## 14. 정책 실험

이후 확장 기능으로 가격상한제와 가격하한제를 구현할 수 있도록 설계한다.

예:

시장 균형가격:
5,000원

사용자가 가격상한:
3,000원

으로 설정한다.

그러면:

가격상한 설정
→ 소비자 수요 증가
→ 생산자 공급 감소
→ 수요량 > 공급량
→ 초과수요 발생

이라는 과정이 애니메이션 또는 단계별 설명으로 나타나게 한다.

그래프에서도 부족한 양을 직관적으로 표시한다.


## 15. 개념 페이지

"개념" 페이지에서는 경제학 용어를 아주 쉽게 설명한다.

예:

수요
"사람들이 어떤 가격에서 사고 싶어 하는 양"

공급
"판매자가 어떤 가격에서 팔고 싶어 하는 양"

균형가격
"사고 싶어 하는 양과 팔고 싶어 하는 양이 만나는 가격"

각 개념에는:

[직접 실험해보기]

버튼을 넣는다.

즉 개념 설명에서 바로 해당 실험으로 이동할 수 있도록 한다.


## 16. 기록 페이지

사용자가 완료한 실험과 저장한 경제 원리를 볼 수 있도록 한다.

예:

최근 실험
- 수요와 공급
- 탄력성
- 가격상한제

저장한 원리
- 수요 증가 → 가격 상승
- 공급 감소 → 가격 상승
- 가격 상승 → 수요량 감소

처음에는 실제 회원가입이나 서버 저장 기능 없이 localStorage를 사용해도 된다.


## 17. 그래프 구현

그래프는 단순한 이미지가 아니라 실제 인터랙티브 그래프로 구현한다.

사용자가 슬라이더를 움직이면 그래프가 즉시 업데이트되어야 한다.

가능하면 React 기반의 차트 라이브러리를 사용한다.

그래프는 모바일에서 터치하기 편해야 한다.

그래프에 너무 많은 정보를 넣지 않는다.

가장 중요한 것은:
"그래프가 어떻게 변했는지 한눈에 알 수 있는 것"

이다.


## 18. 애니메이션

경제 변화가 발생할 때 즉시 숫자만 바뀌는 것이 아니라 변화 과정을 짧게 보여준다.

예:

수요 증가

1. 소비자 구매 의향 증가
↓
2. 수요곡선 이동
↓
3. 새로운 균형점 형성
↓
4. 가격과 수량 변화

단, 애니메이션은 과도하게 화려하지 않게 한다.

학습을 방해하지 않는 부드러운 애니메이션을 사용한다.


## 19. UX 원칙

가장 중요한 UX 원칙:

"사용자가 지금 무엇을 조작하고 있는지 항상 알아야 한다."

"왜 결과가 나왔는지 항상 설명할 수 있어야 한다."

"경제학 용어를 몰라도 사용할 수 있어야 한다."

"한 화면에 너무 많은 개념을 넣지 않는다."

"모바일에서 한 손으로 조작하기 편해야 한다."

"그래프를 보고 겁먹지 않도록 시각적으로 친근하게 만든다."


## 20. 기술적인 구현 방향

React 기반으로 구현한다.

컴포넌트를 기능별로 분리한다.

예:

Home
ExperimentList
Experiment
DemandSupplySimulation
ElasticitySimulation
ConceptList
ConceptDetail
SavedPrinciples
BottomNavigation

경제 시뮬레이션의 계산 로직과 UI를 분리한다.

경제학 계산값은 처음에는 교육용으로 단순화된 모델을 사용한다.

코드를 수정하기 쉽도록 경제학 모델을 별도의 파일이나 함수로 관리한다.

예:
economicModels/
- supplyDemand.js
- elasticity.js
- priceControl.js

각 실험의 설명 문구도 별도의 데이터 구조로 관리하여 나중에 쉽게 수정하고 추가할 수 있게 한다.


## 21. 중요한 개발 순서

처음부터 모든 경제학 기능을 구현하지 않는다.

1단계:
전체 사이트 UI/레이아웃 구축

2단계:
홈 화면 완성

3단계:
실험 목록 페이지

4단계:
수요·공급 실험 하나를 완성도 높게 구현

5단계:
"왜 이렇게 됐나요?" 인과관계 설명 기능 구현

6단계:
개념 페이지 구현

7단계:
저장 기능 구현

8단계:
탄력성/가격상한제 등 추가 실험 확장

처음 목표는 "수요와 공급 실험 하나를 정말 잘 만드는 것"이다.


## 22. 최종적으로 원하는 느낌

이 사이트를 처음 방문한 경제학 초보자가

"경제학은 어렵다."

가 아니라

"내가 직접 움직여보니까 왜 이렇게 되는지 알겠다."

라고 느끼게 만들어야 한다.

따라서 복잡한 금융 대시보드나 대학 경제학 강의자료 같은 디자인은 피한다.

"인터랙티브 교과서 + 실험실 + 모바일 학습 앱"

의 느낌으로 디자인한다.

전체 사이트를 실제 서비스처럼 완성도 있게 만들어라.

코드는 유지보수하기 쉽게 작성하고,
반응형을 고려하되 모바일 화면을 최우선으로 한다.
